# กติกาของฐานข้อมูล

> ตารางหนึ่งตารางหน้าตาเป็นยังไง · อะไรอยู่ใน `.prisma` อะไรอยู่ใน `.sql`
> และสี่ข้อที่ห้ามผิด

---

## ตารางหนึ่งตารางอยู่ในสองไฟล์ ไม่ใช่ไฟล์เดียว

**นี่คือกับดักที่แพงที่สุดของขั้นสคีมา** — เขียนแค่ไฟล์แรกแล้วคิดว่าจบ
คือตารางที่ไม่มีข้อบังคับใดเลยนอกจากชนิดข้อมูล

| ไฟล์ | ถืออะไร |
|---|---|
| `apps/api/prisma/schema/<domain>.prisma` | model · ฟิลด์ · ความสัมพันธ์ · `@@index` ธรรมดา |
| `apps/api/prisma/sql/parts/NN-<เรื่อง>.sql` | **partial unique · CHECK · `COMMENT ON` · index มีเงื่อนไข** |

Prisma เขียน `WHERE deleted_at IS NULL` ต่อท้าย unique index ไม่ได้ ซึ่งเป็นรูปแบบ
ที่ทุกตารางที่ soft delete ต้องใช้ · และเขียน CHECK ไม่ได้ ซึ่งเป็นสิ่งที่คู่
`<verb>At`/`<verb>By` ทุกคู่ต้องมี

รันด้วย `bun run db:push` เท่านั้น — **`prisma db push` เปล่า ๆ จะลบ partial unique
ทิ้งเงียบ ๆ** เพราะไม่มีอะไรในสคีมาอธิบายว่ามันควรมีอยู่

ดูบรรทัด `patch.sql applied — N/N statements` ตอนจบ · เลขไม่ตรงกันแปลว่ามีคำสั่งหล่น

## กฎเหล็กสี่ข้อ

### ข้อ 1 — `user` ต้องเป็นตารางแรกเสมอ

audit block ของทุกตารางชี้มาที่ `user.id` · ตารางที่สร้างก่อนมันคือตารางที่
`createdBy` ชี้ไปยังสิ่งที่ยังไม่มีอยู่

**`user.createdBy` เป็น `null` ได้แถวเดียวในระบบ** — แถวแรกที่ seed สร้าง
ซึ่งไม่มีคนสร้าง

**ห้ามให้มันชี้ตัวเอง (`createdBy = 1`)** เด็ดขาด · การทำแบบนั้นต้อง insert
โดยระบุ `id` เอง แล้ว sequence จะไม่ขยับ · แถวถัดไปจะขอเลข 1 ที่ถูกใช้ไปแล้ว
และ `db:reset` จะพังทุกครั้งหลังจากนั้น

### ข้อ 2 — soft delete ต้องใช้ partial unique เสมอ

```sql
CREATE UNIQUE INDEX IF NOT EXISTS role_name_live_key
  ON role (name) WHERE deleted_at IS NULL;
```

**ห้ามใช้ `@unique` เปล่า ๆ บนตารางที่ soft delete** · มันจะจองชื่อที่ถูกลบไปแล้ว
ไว้ตลอดกาล — คนที่ลบบทบาท "สัตวแพทย์" ทิ้งเพราะพิมพ์ผิด จะสร้างชื่อเดิม
ที่ถูกต้องอีกไม่ได้

ข้อยกเว้นเดียวคือตารางที่ **ไม่มี** `deletedAt` เลย (`user` · `pet_owner_account`)
ที่นั่นไม่มีแถวที่ต้องยกเว้น `@unique` เปล่าจึงถูกต้อง

unique ที่มีขอบเขต (ไม่ซ้ำ **ในสาขาเดียวกัน**) เขียนด้วยมือทั้งหมด
Prisma แสดงไม่ได้เลย

### ข้อ 3 — `findUnique` ห้ามใช้กับ business key

partial unique เป็น index ที่ Prisma มองไม่เห็น · `findUnique` จึงเรียกมันไม่ได้
และจะบังคับให้ไปใช้ `@unique` เปล่าแทน ซึ่งผิดข้อ 2

**ใช้ `findFirst` พร้อม `where: { ..., deletedAt: null }` ที่เขียนออกมาเต็ม ๆ**

`findUnique` ใช้ได้กับ `id` และกับ unique จริง ๆ ที่ไม่มีเงื่อนไข
(`user.username` · `pet_owner_account.googleSub` · `*.tokenHash`)

### ข้อ 4 — ไม่มีใครเรียกด้วยรหัส ก็ไม่ต้องมีคอลัมน์รหัส

ถามคำถามนี้ก่อนใส่ `code`: **"ในชีวิตจริง มีใครเรียกของสิ่งนี้ด้วยรหัสไหม"**

ไม่มี = ไม่ใส่ ให้ `name` เป็น business key แทน · คอลัมน์รหัสที่ไม่มีใครใช้
คือช่องที่ทุกฟอร์มต้องมี ทุกคนต้องกรอก และไม่มีใครอ่าน

## audit block — สามแบบ ตามชนิดของตาราง

เลือกแบบตาม**สิ่งที่ตารางเก็บ** ไม่ใช่ตามความเคยชิน

### แบบธุรกิจ — 6 คอลัมน์

ของที่คนสร้าง คนแก้ และวันหนึ่งอาจอยากได้คืน

```prisma
deletedAt DateTime? @map("deleted_at")
deletedBy BigInt?   @map("deleted_by")
createdAt DateTime  @default(now()) @map("created_at")
createdBy BigInt    @map("created_by")
updatedAt DateTime  @updatedAt @map("updated_at")
updatedBy BigInt    @map("updated_by")
```

พร้อม CHECK บังคับให้คู่ At/By มาด้วยกัน:

```sql
ALTER TABLE role ADD CONSTRAINT role_deleted_pair_check
  CHECK ((deleted_at IS NULL) = (deleted_by IS NULL));
```

### แบบ junction — 2 คอลัมน์ hard delete

`role_permission` เป็นตัวอย่าง · การถอนความสัมพันธ์คือการเอาแถวออก
ไม่ใช่การเก็บแถวที่บอกว่า "เคยผูกกัน" ไว้ให้ทุกคิวรีต้องกรองทิ้ง

```prisma
createdAt DateTime @default(now()) @map("created_at")
createdBy BigInt   @map("created_by")
```

ไม่มี `updatedAt`/`updatedBy` เพราะแถวแบบนี้ไม่มีอะไรให้แก้ — มันมีหรือไม่มี

### แบบบันทึก — `createdAt` อย่างเดียว

`login_log` · `audit_log` · เซสชัน · ระบบเขียนเอง ไม่มีใครแก้ ไม่มีใครลบ

เซสชัน (`user_session` · `pet_owner_session`) **hard delete เท่านั้น** —
"แถวมีอยู่" ต้องแปลว่า "ยังใช้ได้" ตรง ๆ ไม่ต้องมีเงื่อนไขอื่นอ่านประกอบ ·
เซสชันที่ soft delete แล้วยังค้างอยู่ คือแถวที่คิวรีตัวไหนลืมกรอง
ก็ปล่อยคนที่ถูกถอนสิทธิ์ไปแล้วเข้ามาได้

## ชนิดข้อมูล

| ใช้กับ | ชนิด | เพราะ |
|---|---|---|
| id ทุกตัว | `BigInt` | **ออกจาก JSON เป็น `number` เสมอ** แปลงที่ชั้น route |
| เงิน | `Decimal @db.Decimal(12, 2)` | `0.1 + 0.2 !== 0.3` · **บนสายเป็น string** |
| ข้อความ | `String @db.VarChar(n)` | ระบุความยาวเสมอ · `Text` เฉพาะที่ยาวไม่จำกัดจริง ๆ |
| วันเวลา | `DateTime` | เก็บ UTC · `TZ=Asia/Bangkok` ตอนแสดง |
| จริง/เท็จ | `Boolean` | ตั้งชื่อให้ตอบคำถาม yes/no · เลี่ยงชื่อปฏิเสธ |
| ตัวเลือกตายตัว | `enum` | ค่าที่โค้ดตัดสินใจจากมัน · ไม่ใช่ของที่ผู้ใช้เพิ่มเองได้ |

**คอลัมน์ที่เก็บ hash ต้องมีคำว่า `Hash` ในชื่อ** (`passwordHash` · `tokenHash`)
เพราะสิ่งที่อยู่ข้างในไม่ใช่รหัสผ่านและไม่ใช่ token · ชื่อที่บอกไม่ครบ
คือชื่อที่ทำให้มีคนเอาไปเทียบตรง ๆ สักวัน

**`null` แปลว่าอะไร ต้องเขียนไว้ใน `///`** ทุกครั้งที่มันไม่ชัดในตัวเอง

## `onDelete` — Prisma ตั้งให้เองตามรูปของ FK

| FK เขียนแบบไหน | ได้อะไร | ลบแม่ได้ไหม |
|---|---|---|
| `BigInt?` (ว่างได้) | `SET NULL` | **ได้** ลูกถูกล้างค่าเงียบ ๆ |
| `BigInt` (บังคับ) | `RESTRICT` | ไม่ได้ ฐานปฏิเสธ |

"ลบแม่ที่มีลูกอยู่ไม่ได้" จึงบังคับด้วยกลไกคนละตัวขึ้นกับว่า FK ว่างได้หรือไม่ ·
**เป็นการตัดสินใจของผู้ใช้** ว่าจะใส่ `@relation(..., onDelete: Restrict)` เพิ่มไหม
ไม่ใช่ของที่เดาแทนได้

## `COMMENT ON` ภาษาไทย

ทุกตารางต้องมี `COMMENT ON TABLE` · คอลัมน์ที่ความหมายไม่ชัดในชื่อต้องมี
`COMMENT ON COLUMN`

```sql
COMMENT ON TABLE "user" IS 'บัญชีผู้ใช้หลังบ้าน (พนักงานคลินิก) — ระงับได้ ลบไม่ได้';
COMMENT ON COLUMN "user".locked_at IS 'ถูกล็อกเพราะรหัสผิดครบจำนวน ไม่ปลดเอง ต้องมีผู้ดูแลมาปลด';
```

เพราะคนที่เปิด `db:studio` หรือต่อฐานตรง ๆ ไม่ได้อ่าน `///` ในสคีมา

**`user` เป็นคำสงวนของ SQL — ต้องใส่ `"..."` ทุกครั้ง**

## ทุกคำสั่งใน `sql/parts/` ต้องรันซ้ำได้

มันรันใหม่ทุกครั้งที่ `db:push`

```sql
CREATE UNIQUE INDEX IF NOT EXISTS ...
ALTER TABLE x DROP CONSTRAINT IF EXISTS x_check;
ALTER TABLE x ADD CONSTRAINT x_check CHECK (...);
```

ไฟล์ตั้งชื่อขึ้นต้นด้วยเลขสองหลัก — `patch.ts` รันเรียงตามชื่อไฟล์

## พิสูจน์กับฐานจริง ไม่ใช่แค่ push ผ่าน

`db:push` ผ่าน แปลว่า Prisma พอใจ · ไม่ได้แปลว่าข้อบังคับทำงาน

เขียนสคริปต์ทิ้งขว้าง (`apps/api/_ชื่อ.ts` — gitignore ครอบไว้แล้ว) แล้ว
**ลองยิงสิ่งที่ควรถูกปฏิเสธจริง ๆ** · ข้อความของข้อบังคับกับพฤติกรรมจริง
เคยไม่ตรงกันมาแล้ว

อ่านโครงที่ได้จริงจาก `information_schema.columns` · `pg_indexes` · `pg_constraint`

> `conrelid::regclass` ต้อง cast `::text` ไม่งั้น adapter โยน `P2010`
> (วัดเมื่อ 2026-08-31 · Prisma 7.10 + `@prisma/adapter-pg`)

แล้ว**ลองลบแม่ที่มีลูกจริง ๆ** ดูว่าฐานปฏิเสธตามที่คิดไว้ไหม
