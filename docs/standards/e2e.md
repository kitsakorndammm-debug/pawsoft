# เทส e2e — Playwright

> ยิงของจริงทั้งกอง: เบราว์เซอร์ → เว็บ → API → ฐาน
>
> ชุดนี้มีไว้จับสิ่งที่ typecheck กับ unit test มองไม่เห็น

---

## รันยังไง

```bash
bun run e2e:prep    # ครั้งแรก และทุกครั้งที่ schema เปลี่ยน
bun run e2e         # รันทั้งหมด
```

## ด่านทั้งหมดก่อนส่งงาน

```bash
bun run typecheck        # API
bun run typecheck:web    # web
bun run test             # unit (เร็ว · ไม่แตะฐาน dev)
bun run e2e:prep         # ครั้งแรก และทุกครั้งที่ schema เปลี่ยน
bun run e2e              # เบราว์เซอร์จริง
bun run build:web        # build ผ่านไหม
```

**`bun run test` ต้องมีไฟล์เทสอย่างน้อยหนึ่งไฟล์** — `bun test` ที่ไม่เจอไฟล์เลย
exit code 1 · CI จะแดงโดยไม่มีอะไรพัง (เจอ 2026-09-01)

---

| คำสั่ง | ทำอะไร |
|---|---|
| `bun run e2e` | รันทั้งหมด (staff + owner) |
| `bun run e2e:ui` | เปิดหน้าจอ Playwright ไล่ดูทีละขั้น |
| `bun run e2e:report` | เปิดรายงานของรอบล่าสุด |
| `bunx playwright test --project=owner` | เฉพาะฝั่งลูกค้า |
| `bunx playwright test -g "จองคิว"` | เฉพาะเทสที่ชื่อมีคำนั้น |

**ไม่ต้องเปิดเซิร์ฟเวอร์เอง** — `webServer` ใน `playwright.config.ts` เปิด API (3211)
กับเว็บ (3210) ให้ แล้วปิดตอนจบ

## ทำไมต้องมี ทั้งที่มี typecheck แล้ว

บั๊กสามตัวที่เจ็บที่สุดของโปรเจคนี้ **รอด typecheck มาได้ทั้งหมด**:

| บั๊ก | typecheck | สิ่งที่เกิดขึ้นจริง |
|---|---|---|
| `/api/appointments/slots` การ์ดด้วยสิทธิ์พนักงาน | เขียว | หน้าจองของลูกค้าได้ 401 เงียบ ๆ · ปุ่มจองกดไม่ได้ |
| route ส่ง `status: 'PENDING'` แต่ service ไม่หยิบไปใช้ | เขียว | ใบจองกลายเป็น `BOOKED` โดยไม่มีใครยืนยัน |
| `CREATE UNIQUE INDEX IF NOT EXISTS` ข้ามการแก้เงื่อนไข | เขียว | index เก่ายังบังคับกฎเดิม · จองซ้ำได้ |

ทั้งสามตัวเห็นได้ต่อเมื่อกดปุ่มจริงบนหน้าจริง

## ฐานข้อมูล — **สามฐาน ไม่ใช่สอง**

| ฐาน | ใครใช้ | คำสั่ง |
|---|---|---|
| `pawsoft` | เครื่อง dev | `bun run db:push` |
| `pawsoft_test` | `bun test` | `bun run db:push:test` |
| `pawsoft_e2e` | Playwright | `bun run e2e:prep` |

**ใช้ฐานร่วมกันไม่ได้** — เทสสร้างและลบข้อมูลตลอดเวลา · ใช้ฐานเดียวกับที่กำลังเปิด
หน้าจอดูอยู่ แปลว่าข้อมูลที่กำลังดูหายไปกลางคัน

`bun run e2e:prep` สั่ง `--force-reset` ซึ่ง**ล้างฐานนั้นทั้งหมด** · สคริปต์มีด่านกัน
ไม่ให้ชี้ไปฐานอื่นนอกจาก `pawsoft_e2e`

## บัญชีที่ seed ไว้ — **คนละสิทธิ์กัน ไม่ใช่ admin ตัวเดียว**

| ผู้ใช้ | สิทธิ์ | ใช้พิสูจน์อะไร |
|---|---|---|
| `e2e_counter` | reception + billing:collect | เคาน์เตอร์ · **ลงผลวินิจฉัยไม่ได้** |
| `e2e_vet` | medical:write | หมอลงผลวินิจฉัย |
| `e2e_account` | billing:verify | บัญชียืนยันยอด · **ต้องไม่ใช่คนที่ส่ง** |

รหัสผ่านทั้งหมด `e2e-pass-1234` (`admin` ใช้ `1234`)

**เทสที่ล็อกอิน admin อย่างเดียวจะเขียวทั้งที่กฎพวกนี้พังอยู่** เพราะ admin ผ่านทุกด่าน

## ฝั่งลูกค้าล็อกอินยังไง — ข้าม Google

`POST /api/owner-auth/test-login` **เปิดเฉพาะ `APP_ENV=local`** · ตอบ 404 เมื่อปิด

เทสที่ต้องผ่านหน้าเลือกบัญชีของ Google จริงคือเทสที่รันใน CI ไม่ได้ (ต้องมีบัญชีจริง ·
ผ่าน 2FA · Google บล็อกเบราว์เซอร์อัตโนมัติ) · สิ่งที่เทสฝั่งนี้ต้องพิสูจน์คือหน้าจอ
**หลัง**ล็อกอิน ไม่ใช่ว่า OAuth ของ Google ทำงานไหม

## กฎการเขียน

**อ่าน DOM จริงก่อนเขียน selector** — เดาแล้วผิดจะได้เทสที่ล้มด้วยเหตุผลที่ไม่เกี่ยว
กับโค้ด · ล้มแล้วดูที่ `e2e/.output/<ชื่อเทส>/error-context.md` ซึ่งมีผัง DOM ตอนล้ม

รูปที่เจอบ่อย:

| เขียนแบบนี้ | ได้จริงเป็น |
|---|---|
| `getByRole('button', { name: 'เลือกชนิด' })` | `combobox` ไม่ใช่ `button` |
| กด "ออกจากระบบ" แล้วรอ URL | มี `alertdialog` ยืนยันคั่น |
| กดปุ่มทันทีหลัง `goto` | ปุ่ม `disabled` จนกว่า query จะตอบ — ต้อง `toBeEnabled()` ก่อน |

**รอสถานะ ไม่ใช่รอเวลา** — `waitForTimeout` คือเทสที่ล้มแบบสุ่มบนเครื่องที่ช้ากว่า

**ชื่อไม่ซ้ำทุกครั้งที่รัน** — ใช้ `uniq()` · ระบบมี unique หลายตัว (เบอร์โทร · เลขคิว
ต่อวัน) และเทสที่รันซ้ำไม่ได้คือเทสที่ไม่มีใครกล้ารัน

## ตรวจว่าชุดเทสจับบั๊กได้จริง

ชุดที่เขียวเสมอไม่ได้แปลว่าโค้ดถูก — อาจแปลว่าเทสไม่ได้ตรวจอะไรเลย

วิธีพิสูจน์: **ใส่บั๊กที่เคยเกิดจริงกลับเข้าไป แล้วดูว่าเทสแดงไหม**

ทำแล้วเมื่อ 2026-09-01 — คอมเมนต์ `status: 'PENDING'` ออกจาก route แล้วเทส
"ลูกค้าใหม่: กรอกข้อมูล → เพิ่มสัตว์ → จองคิว" แดงตามคาด · คืนค่าแล้วเขียวเหมือนเดิม

---

## บั๊กจริงที่ชุดนี้จับได้

**`api.post` ทำลาย `FormData` ทุกครั้ง** (2026-09-01)

```ts
const json = (body: unknown) => JSON.stringify(body)   // <- FormData กลายเป็น "{}"
```

`JSON.stringify(formData)` คืน `"{}"` เพราะ `FormData` ไม่มี property ให้ serialize ·
ผลคือ **ลูกค้าอัปสลิปกับอัปรูปสัตว์ไม่ได้เลย** — BE เห็น body ว่างแล้วตอบ
"ต้องแนบไฟล์มาด้วย" ทั้งที่ผู้ใช้แนบมาแล้ว

typecheck ไม่เห็นเพราะ `JSON.stringify` รับ `unknown` ได้หมด · เทส API ไม่เห็นเพราะ
ยิงด้วย `fetch` ตรง ๆ ไม่ผ่าน `api-client` · **เห็นได้ต่อเมื่อกดปุ่มจริงบนเบราว์เซอร์จริง**

## กับดักของเทสที่ยิงของจริง

| อาการ | สาเหตุ |
|---|---|
| ผ่านตอนรันเดี่ยว ล้มตอนรันทั้งชุด | ข้อมูลชนกัน — สลิปกันซ้ำด้วย sha256 · เบอร์โทร unique · เลขคิวต่อวัน |
| ปุ่มกดแล้วไม่เกิดอะไร | กดตอน query ยังโหลด — ต้อง `toBeEnabled()` ก่อนเสมอ |
| กล่องไม่ปิดหลังบันทึก | ฟอร์มติด validation ที่มองไม่เห็น — เปิดภาพใน `.output/` ดู |
| รอข้อความในกล่องที่ปิดไปแล้ว | ยืนยันที่ผลลัพธ์ (แถวในตาราง · สถานะ) ไม่ใช่ที่ข้อความชั่วคราว |
