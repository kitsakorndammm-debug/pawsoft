# ขอ Google OAuth มาใส่ `.env`

> คู่มือสำหรับคนที่ไม่เคยทำมาก่อน · ทำครั้งเดียวต่อหนึ่งโปรเจค แล้วได้สองค่า:
> `GOOGLE_CLIENT_ID` กับ `GOOGLE_CLIENT_SECRET`
>
> ใช้กับฝั่งเจ้าของสัตว์เท่านั้น — ฝั่งพนักงานล็อกอินด้วย username/password
> ไม่เกี่ยวกับ Google เลย (`auth.md`)

---

## 1 · สร้างโปรเจคใน Google Cloud

เข้า [console.cloud.google.com](https://console.cloud.google.com)

ที่แถบบนสุดมีตัวเลือกโปรเจค → **New Project** → ตั้งชื่อ (เช่น `Paw Soft`) → **Create**

**ตั้งชื่อให้คนอื่นอ่านออก** — บัญชี Google หนึ่งบัญชีมีโปรเจคได้หลายอัน และหน้าจอนี้
แสดงแต่ชื่อ · โปรเจคชื่อ `My Project 47821` คือโปรเจคที่อีกหกเดือนไม่มีใครกล้าลบ
เพราะไม่รู้ว่ามันคืออะไร

สร้างเสร็จแล้ว **ต้องเลือกโปรเจคนั้นให้ active ก่อน** — ขั้นถัดไปทั้งหมดทำในโปรเจค
ที่เลือกอยู่ตอนนั้น การตั้งค่าที่ไปลงผิดโปรเจคเป็นสาเหตุที่พบบ่อยของ `invalid_client`

## 2 · OAuth consent screen — หน้าที่ผู้ใช้เห็นตอนกดอนุญาต

เมนูซ้าย → **APIs & Services** → **OAuth consent screen**

| ช่อง | ใส่อะไร |
|---|---|
| User Type | **External** |
| App name | ชื่อที่ผู้ใช้จะเห็น — `Paw Soft` |
| User support email | อีเมลที่ผู้ใช้ติดต่อกลับได้ |
| Developer contact information | อีเมลของคนดูแลระบบ |

**External ไม่ได้แปลว่าใครก็เข้าได้** — Internal มีให้เลือกเฉพาะบัญชีที่อยู่ใน
Google Workspace ขององค์กร และจำกัดให้เฉพาะคนในองค์กรนั้นล็อกอินได้ ·
ลูกค้าของคลินิกใช้ Gmail ส่วนตัว จึงต้องเป็น External

### Scopes — เอาแค่สามตัว ไม่เอามากกว่านั้น

| scope | ได้อะไรมา |
|---|---|
| `openid` | ยืนยันว่าคนนี้คือใคร (ได้ `sub` — id ที่ไม่เปลี่ยนของบัญชีนั้น) |
| `email` | อีเมล |
| `profile` | ชื่อ · รูปโปรไฟล์ |

สามตัวนี้ Google เรียกว่า **non-sensitive scopes** และเป็นทุกอย่างที่ระบบนี้ต้องใช้ —
เรารู้แค่ว่า "คนที่กดเข้ามาคือเจ้าของบัญชีนี้" ก็พอแล้ว

**ขอมากกว่านี้มีราคาที่ต้องจ่าย** — scope ที่ Google จัดว่า sensitive หรือ restricted
(ปฏิทิน · ไดรฟ์ · รายชื่อผู้ติดต่อ) ทำให้แอปต้องเข้ากระบวนการ **verification review**
ก่อนเผยแพร่ ซึ่งใช้เวลาเป็นสัปดาห์ ต้องส่งวิดีโอสาธิต และต้องมีนโยบายความเป็นส่วนตัว
บนโดเมนจริง

ระบบนี้ไม่ได้ใช้ข้อมูลพวกนั้นเลย · ขอไว้ก่อน "เผื่อได้ใช้" คือการจ่ายค่านั้นฟรี ๆ
และผู้ใช้ก็เห็นรายการสิทธิ์ที่ยาวขึ้นตอนกดอนุญาต ซึ่งทำให้คนกดยกเลิกมากขึ้น

### Testing กับ Production

หลังสร้างเสร็จ แอปจะอยู่ในสถานะ **Testing** ก่อนเสมอ

| สถานะ | ใครล็อกอินได้ |
|---|---|
| **Testing** | เฉพาะอีเมลที่ใส่ไว้ในลิสต์ **Test users** · สูงสุด 100 บัญชี |
| **Production** | ใครก็ได้ |

ตอนพัฒนา ให้เติมอีเมลของตัวเองและของคนที่จะช่วยทดสอบ เข้าลิสต์ Test users ·
**บัญชีที่ไม่อยู่ในลิสต์จะเจอ `access_blocked`** ไม่ใช่หน้าล็อกอินปกติ

**กดปุ่ม Publish app เพื่อขึ้น Production ได้เลย ไม่ต้องรอรีวิว** — เพราะสาม scope
ที่เราขอเป็น non-sensitive ทั้งหมด · verification review จะบังคับก็ต่อเมื่อขอ scope
ที่ Google จัดว่า sensitive ขึ้นไป ซึ่งเราไม่ได้ขอ

## 3 · สร้าง OAuth client ID

เมนูซ้าย → **APIs & Services** → **Credentials** →
**Create Credentials** → **OAuth client ID** → Application type: **Web application**

### Authorized JavaScript origins

```
http://localhost:3200
```

คือที่อยู่ของ **หน้าเว็บ** ที่ผู้ใช้กำลังเปิดอยู่ตอนกดปุ่มล็อกอิน

### Authorized redirect URIs

```
http://localhost:3201/api/owner-auth/google/callback
```

คือที่อยู่ของ **API** ที่ Google จะพาผู้ใช้กลับมาหลังกดอนุญาต — คนละพอร์ตกับข้างบน
เพราะเป็นคนละแอป (3200 คือ web · 3201 คือ api)

**`owner-auth` ไม่ใช่ `auth`** — prefix นี้มาจาก `ownerAuthRoutes` ใน
`apps/api/src/modules/owner-auth/owner-auth.routes.ts` และตั้งชื่อแยกเพราะฝั่งพนักงาน
มีเส้นล็อกอินของตัวเองอยู่แล้ว · เขียนเป็น `/api/auth/...` จะได้ 404 ซึ่ง Google
รายงานกลับมาเป็น `redirect_uri_mismatch` ที่ชี้ไปผิดทาง (เคยพลาดจริงมาแล้ว 2026-09-01
— ทั้ง `.env` และเอกสารนี้เขียนผิดพร้อมกัน)

**ต้องตรงกับค่า `GOOGLE_REDIRECT_URI` ใน `.env` ทุกตัวอักษร**

### สามข้อที่พลาดบ่อยที่สุด

**1 · `localhost` กับ `127.0.0.1` เป็นคนละที่ในสายตา Google**

ทั้งที่มันชี้ไปเครื่องเดียวกัน · ถ้าเปิดเว็บด้วยสองแบบสลับกัน **ต้องลงทะเบียนทั้งคู่**
ไม่งั้นแบบที่ไม่ได้ลงจะเจอ `redirect_uri_mismatch`

**2 · ตรงกันหมายถึงตรงจริง ๆ**

`http` ≠ `https` · พอร์ตต่างกันคือคนละที่ · **และ `/callback` กับ `/callback/`
เป็นคนละ URI** — เครื่องหมาย `/` ตัวเดียวท้ายสุดทำให้ไม่ผ่าน

**3 · โดเมนจริงต้องเป็น https เท่านั้น**

ข้อยกเว้นเรื่อง http มีให้แค่ `localhost` กับ `127.0.0.1` เท่านั้น · IP ในวง LAN
อย่าง `http://192.168.1.50:3200` **ลงทะเบียนไม่ได้เลย** Google ปฏิเสธตั้งแต่ตอนกดบันทึก
(เหตุผลและผลกระทบอยู่ที่ `auth.md`)

**ตอนขึ้น production ให้เพิ่มเข้าไป ไม่ใช่ลบของเดิมทิ้ง** — ลบ localhost ออกเมื่อไหร่
เครื่อง dev ทุกเครื่องล็อกอินไม่ได้ทันที · ช่องนี้ใส่ได้หลายบรรทัด

## 4 · เอาค่ามาใส่ `.env`

กด Create แล้ว Google จะขึ้นกล่องที่มีสองค่า — **คัดลอกตอนนั้นเลย**
Client secret ดูย้อนหลังไม่ได้ (ถ้าพลาด กด Reset secret แล้วได้ตัวใหม่)

```env
GOOGLE_CLIENT_ID=xxxxxxxx.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-xxxxxxxxxxxx
GOOGLE_REDIRECT_URI=http://localhost:3201/api/owner-auth/google/callback
```

**`.env` ไม่เข้า git** — `.gitignore` กันไว้แล้ว · secret ที่ commit ไปครั้งเดียว
ถือว่ารั่วถาวร ต่อให้ลบ commit ทีหลัง เพราะมันอยู่ใน history ของทุกคนที่เคย clone
วิธีแก้คือ Reset secret ที่ Google ไม่ใช่การแก้ประวัติ git

**ไม่ตั้งค่าพวกนี้ก็บูตได้** — ต่างจาก `SEED_ADMIN_PASSWORD` ที่ไม่ตั้งแล้ว API
ไม่ขึ้นเลย · เส้นทาง Google จะตอบ 503 พร้อมข้อความว่ายังไม่ได้ตั้งค่า
ซึ่งอ่านออกกว่าการปล่อยให้ไปถึงหน้า Google แล้วเจอ error ของ Google

## 5 · error ที่เจอบ่อย

| ข้อความ | แปลว่า | แก้ยังไง |
|---|---|---|
| `redirect_uri_mismatch` | URI ที่ระบบส่งไป ไม่มีในลิสต์ที่ลงทะเบียนไว้ | เทียบ `GOOGLE_REDIRECT_URI` กับที่ใน Console **ทีละตัวอักษร** — ดู protocol · พอร์ต · `/` ท้าย |
| `access_blocked` · `App has not completed verification` | แอปยังเป็น Testing และอีเมลที่ใช้ล็อกอินไม่อยู่ในลิสต์ Test users | เติมอีเมลนั้นเข้า Test users หรือกด Publish app |
| `invalid_client` | client id หรือ secret ผิด | ดูว่าคัดลอกครบไม่มีช่องว่างติดมา และดูว่าเอามาจากโปรเจคที่ถูกตัว |
| `Error 400: invalid_request` | ค่าที่ส่งไปไม่ครบหรือผิดรูป | มักเกิดตอน `GOOGLE_CLIENT_ID` ยังว่างอยู่ใน `.env` |

**`redirect_uri_mismatch` เกือบทุกครั้งคือช่องว่างหรือ `/` ท้าย** — ไม่ใช่เรื่องใหญ่กว่านั้น
Google แสดง URI ที่มันได้รับมาในหน้า error ด้วย · เอาไปวางเทียบกับที่ลงทะเบียนไว้ตรง ๆ
แล้วจะเห็นทันทีว่าต่างกันตรงไหน

**การแก้ค่าใน Console บางครั้งใช้เวลาสักครู่กว่าจะมีผล** — แก้แล้วยังเจอ error เดิม
ให้ลองใหม่อีกครั้งก่อนจะไปไล่หาที่โค้ด
