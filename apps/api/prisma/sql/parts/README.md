# `prisma/sql/parts/` — ครึ่งที่ Prisma เขียนไม่ได้

ตารางหนึ่งตารางอยู่ใน **สองไฟล์** เสมอ:

| ไฟล์ | ถืออะไร |
|---|---|
| `prisma/schema/<domain>.prisma` | model · ฟิลด์ · ความสัมพันธ์ · `@@index` ธรรมดา |
| `prisma/sql/parts/NN-<เรื่อง>.sql` | partial unique · CHECK · `COMMENT ON` ภาษาไทย · index มีเงื่อนไข |

**นี่คือกับดักที่แพงที่สุดของขั้นสคีมา** — เขียนแค่ไฟล์แรกแล้วคิดว่าจบ คือตารางที่
ไม่มีข้อบังคับใดเลยนอกจากชนิดข้อมูล

## ทำไมต้องแยก

Prisma เขียน `WHERE deleted_at IS NULL` ต่อท้าย unique index ไม่ได้ ซึ่งเป็นรูปแบบที่
ทุกตารางที่ soft delete ต้องใช้ — ไม่งั้นชื่อที่เคยถูกลบไปแล้วจะกันไม่ให้ใครใช้ชื่อนั้นอีก
ตลอดกาล

CHECK ก็เขียนไม่ได้ และคู่ `<verb>At`/`<verb>By` ทุกคู่ในระบบต้องมีมันบังคับว่าจะมาด้วยกัน
หรือไม่มาเลย

## วิธีรัน

```sh
bun run db:push      # prisma db push แล้วต่อด้วย bun prisma/patch.ts
```

**ห้ามรัน `prisma db push` เปล่า ๆ** — มันมองไม่เห็นไฟล์ในโฟลเดอร์นี้ และจะ **ลบ**
partial unique ทิ้งเงียบ ๆ เพราะไม่มีอะไรในสคีมาที่อธิบายว่ามันควรมีอยู่

`patch.ts` รันผ่าน connection ของ Prisma ไม่ใช่ `psql` — เครื่อง dev ที่เป็น Windows
ไม่มี client ของ Postgres ลงไว้ และฐานอยู่ใน Docker

## กติกาของไฟล์ในโฟลเดอร์นี้

- **ตั้งชื่อขึ้นต้นด้วยเลขสองหลัก** — `patch.ts` รันเรียงตามชื่อไฟล์
- **ทุกคำสั่งต้องรันซ้ำได้** (`IF NOT EXISTS` · `DROP ... IF EXISTS` ก่อน `ADD`) เพราะ
  มันรันใหม่ทุกครั้งที่ `db:push`
- ดูบรรทัด `patch.sql applied — N/N statements` ตอนจบ · ถ้าเลขสองตัวไม่ตรงกัน
  แปลว่ามีคำสั่งหล่นไป
