# ขั้น 4 · web

**หนึ่งใบสั่ง = หนึ่งหน้าจอ** ไม่ใช่ทั้งเมนูรวดเดียว

หน้าจอคือชั้นเดียวที่ผู้ใช้เห็น · ผิดที่นี่แปลว่าผิดต่อหน้าคนใช้งานจริง
ส่วนที่เหลือของระบบถูกทั้งหมดก็ไม่ช่วย

---

## ถามก่อนลงมือ ทุกครั้ง

**ใบสั่งไม่ได้ระบุว่าหน้าไหน → ถาม แล้วหยุดรอ**

หน้าจอไม่มี "operation" แบบ service — มันมีหลายอย่างในหน้าเดียว
จึงต้องถามให้ครบว่าหน้านี้ **ทำอะไรได้บ้าง** ก่อน ไม่ใช่ถามว่าหน้าตายังไง

| ถาม | ไม่ถาม |
|---|---|
| หน้านี้ทำอะไรได้บ้าง — ดู · เพิ่ม · แก้ · ลบ · ลากเรียง | ปุ่มอยู่ซ้ายหรือขวา |
| เพิ่ม/แก้ เป็น dialog หรือหน้าแยก | dialog กว้างกี่พิกเซล |
| ต้องค้น · กรอง · แบ่งหน้าไหม | ช่องค้นสีอะไร |
| ใครเข้าหน้านี้ได้ — พนักงาน (permission key ไหน) หรือเจ้าของสัตว์ | เมนูเรียงยังไง |

**การจัดวางตัดสินเองได้** ตามที่ `docs/standards/ui-design.md` เขียนไว้ —
ถามเรื่องพวกนี้ทีละข้อคือการให้ผู้ใช้ออกแบบแทน

**สิ่งที่หน้านี้ทำได้ ตัดสินเองไม่ได้** — เดาว่า "น่าจะมีปุ่มลบด้วย" แล้วทำไป
คือฟีเจอร์ที่ไม่มีใครสั่ง และถ้า BE ไม่มี `delete` ก็คือหน้าที่พังตอนกด

**หน้าของพนักงานกับหน้าของเจ้าของสัตว์เป็นคนละฝั่ง** — คนละเซสชัน คนละ cookie
และหน้าของเจ้าของสัตว์ไม่มี permission key มาเกี่ยวเลย (`docs/standards/auth.md`)

## API ที่หน้านี้ต้องใช้ ต้องมีอยู่จริงก่อน

ดูว่า `apps/api/src/modules/<โมดูล>/*.routes.ts` มี operation ที่หน้านี้ต้องเรียกครบไหม

**ขาดตัวไหน → บอกผู้ใช้ว่าต้องทำขั้น 3 ของตัวนั้นก่อน แล้วรอ**
ห้ามแอบเขียน route เพิ่มเอง (คนละขั้น) และห้ามทำหน้าจอค้างไว้รอ API

**ข้อยกเว้นเดียว: ผู้ใช้สั่งชัดว่าให้ทำ FE ล่วงหน้า** — ทำได้ แต่ต้อง
เขียนไว้ที่ `features/<โดเมน>/api.ts` ว่า BE ยังไม่มี route นี้

## หน้าประกอบจากชิ้นส่วน ไม่ใช่จาก kit ที่คืนทั้งหน้า

**แต่ละหน้าเป็นเจ้าของ `api.ts` · `hooks.ts` · dialog · columns ของตัวเอง**
(ผู้ใช้ตัดสิน 2026-08-26 — kit ที่รับสามพารามิเตอร์แล้วคืนทั้งหน้า ถูกลบทิ้ง)

kit ที่คืนทั้งหน้าทำให้เพิ่มหน้าถูก แต่แก้หน้าเดียวแพง: แก้จุดเดียวกระทบทุกหน้าที่ใช้
และ custom อะไรไม่ได้ถ้าไม่เพิ่ม flag ให้ของกลาง

ชิ้นที่ใช้ซ้ำได้ — **ไม่มีตัวไหนรู้จักโดเมน**:

| ชิ้น | ทำอะไร |
|---|---|
| `DataTable` | หัวตาราง · sticky · sort · filter · pagination |
| `SortableDataTable` | `DataTable` + ลากจัดลำดับ (หน้าที่ไม่ลากใช้ `DataTable` ตรง ๆ) |
| `FormDialog` | หัวกล่อง · ปุ่มล่าง · ปิดหลังบันทึก · error → toast |
| `ListToolbar` | ค้นซ้าย ปุ่มขวา |
| `RowActions` | ดู/แก้/ลบ · เห็นตลอด + คำอธิบายตอนชี้ |
| `Combobox` | ช่องเลือกจากทะเบียนอื่น |

**ลอกหน้าเดิมมาแก้ชื่อได้** — นั่นคือสิ่งที่ตั้งใจ · ของที่ซ้ำจริงอยู่ในชิ้นส่วนแล้ว
ที่เหลือคือสิ่งที่หน้านั้นเป็นเจ้าของ และควรแก้ได้โดยไม่ต้องถามว่าใครใช้อยู่อีก

## อ่านก่อน ทุกครั้ง

| ไฟล์ | เอาอะไรจากมัน |
|---|---|
| `docs/standards/web-conventions.md` | ของแต่ละชิ้นอยู่ที่ไหน · api-client · form · เทส |
| `docs/standards/ui-design.md` | โทเคนสี · ระยะ · ขนาด · ข้อความ |
| `docs/standards/naming.md` | ชื่อไฟล์ · ชื่อ hook · ชื่อเทส |
| `docs/standards/api-conventions.md` | รูปของ response ที่จะได้รับ · ชนิดบนสาย |
| `docs/standards/auth.md` | หน้านี้อยู่ฝั่งไหน · cookie ตัวไหนคุมมัน |
| route ของโมดูลนั้น | ฟิลด์ที่ได้จริง · error code ที่โยนได้ |
| หน้าข้างเคียงที่ทำไปแล้ว | ตัวที่มีอยู่เขียนไว้ยังไง |

**อ่าน route จริง ไม่ใช่เดาจากชื่อ** — ฟิลด์ที่หน้าจอคิดว่ามี แล้ว BE ไม่ได้ส่ง
คือ `undefined` ที่ไปโผล่เป็นช่องว่างบนจอ ไม่ใช่ error

### อ่าน body schema ทีละฟิลด์ ก่อนตัดสินว่าช่องไหนบังคับ

**`required` มาจาก BE ไม่ใช่จากความรู้สึก** — เปิด `<โมดูล>.routes.ts` แล้วดู:

| BE ประกาศ | ฟอร์ม |
|---|---|
| `t.String()` · `t.Number()` | บังคับ · มีดาวแดง |
| `t.Optional(...)` | ไม่บังคับ |
| `t.Union([t.Number(), t.Null()])` | **ไม่บังคับ** — `null` เป็นค่าที่ยอมรับ |

ช่องที่ BE ยอมให้ว่างแต่ฟอร์มบังคับ คือฟอร์มที่ปฏิเสธข้อมูลที่ระบบรับได้ ·
ผู้ใช้ต้องใส่ค่ามั่วเพื่อให้ผ่าน (เกิดจริง 2026-08-26 — วางแผนให้ FK ทุกตัวบังคับ
ทั้งที่สามในสี่ตัวเป็น `nullableId`)

**ดูด้วยว่า `list` แบ่งหน้าไหม** — `paged()` คืน `{ok, data, page}` ไม่ใช่ `{ok, data}`
`api.get()` จะทิ้ง `page` ทิ้งเงียบ ๆ · ตารางที่ต้องแบ่งหน้าใช้ `api.getPaged()`

## ด่าน 1 · ต่อสาย

`features/<โดเมน>/api.ts` — พิมพ์ชนิดของสิ่งที่ endpoint รับและคืน แล้วเรียก `api.*`
`features/<โดเมน>/hooks.ts` — ห่อเป็น `useQuery` / `useMutation`

**หน้าจอเรียก hook เท่านั้น** ไม่เรียก `api.*` ตรง และไม่เรียก `fetch` เด็ดขาด

| ต้องมี | ทำไม |
|---|---|
| query key เป็น `const` ในไฟล์นั้น | `['x','y']` ที่พิมพ์ผิด = invalidate ที่เงียบสนิท ไม่มี error |
| mutation ทุกตัว `invalidateQueries` ใน `onSuccess` | ไม่งั้นแก้เสร็จแล้วตารางยังโชว์ของเก่า |
| ชนิดตรงกับที่ route คืนจริง | `id` เป็น number · เงินเป็น **string** |

**ห้ามแปลงเงินเป็น number** — `Number(price)` คือจุดที่ยอดเริ่มเพี้ยน

## ด่าน 2 · วางหน้า

`app/(auth)/` หน้าที่ยังไม่มี session · `app/(main)/` หน้าหลังล็อกอิน

| ทำ | ไม่ทำ |
|---|---|
| เรียก hook แล้วเอาผลมาแสดง | ยิง API เอง |
| ใช้โทเคนสีของระบบ | พิมพ์ `bg-white` · `text-gray-500` |
| ใช้ `AppForm` + `AppFormField` | เรียก `useForm` เอง |
| ใช้ค่าจาก `lib/routes.ts` | พิมพ์ `'/login'` ตรง ๆ |
| `toast.error(toErrorMessage(err))` | เขียนข้อความปฏิเสธเอง |
| ข้อความ**สำเร็จ**ประกอบเองจาก payload | รอ BE ส่งประโยคสำเร็จมา (มันไม่ส่ง) |
| ซ่อนปุ่มที่ไม่มีสิทธิ์ | ทำปุ่มจางที่กดแล้วเงียบ |
| `'use client'` เฉพาะไฟล์ที่ต้องใช้ | ติดที่ layout |

**ข้อความสำเร็จเป็นหน้าที่ของ FE** — `เพิ่มชนิดสัตว์ "สุนัข" แล้ว`
ไม่ใช่ `บันทึกสำเร็จ` · เอาชื่อจาก**สิ่งที่ BE คืนกลับมา** ไม่ใช่จากที่ผู้ใช้พิมพ์
(BE `trim()` ก่อนบันทึก) · ลบเป็นข้อยกเว้น — คืน `null` จึงต้องจับชื่อไว้ก่อนกด

**ไม่มีสิทธิ์เขียน = หน้าเปลี่ยนหน้าตา ไม่ใช่แค่ปุ่มตาย** — ปุ่มเพิ่มหาย ·
ดินสอกลายเป็นตา (ปุ่มเดียวสลับกัน) · ปุ่มลบหาย · ลากไม่ได้แต่ที่ยังจองไว้
รายละเอียดอยู่ที่ `ui-design.md`

**ปุ่มที่สร้างหรือบันทึกเป็นเขียว** `variant="success"` · ปุ่มลบในหน้าเป็น `destructiveSolid` ·
**แต่ปุ่มยืนยันในกล่องยืนยันเป็นเขียวเสมอ รวมปุ่มลบ** (`ConfirmDialog` ไม่มีตัวเลือกสี) ·
ยกเลิกเป็น `outline` · เขียวสงวนไว้ให้การเขียนข้อมูลเท่านั้น

**ปุ่มไอคอนต้องมี tooltip** — ข้อความเดียวกับ `aria-label` และบอกทั้งการกระทำ
กับสิ่งที่จะโดน (`แก้ไข สมชาย ใจดี`) · ไอคอนอย่างเดียวคือการให้ผู้ใช้เดา

**ฟอร์มจัดเป็นแถว ไม่ใช่หนึ่งช่องหนึ่งบรรทัด** — ช่องที่เป็นของสิ่งเดียวกัน
(ชื่อ · นามสกุล · ชื่อเล่น) อยู่แถวเดียวกันด้วย `sm:grid-cols-N` · สองถึงสามช่องต่อแถว ·
แปดช่องเรียงลงมาแปดบรรทัดคือกล่องที่ต้องเลื่อน และทิ้งพื้นที่แนวนอนไปเปล่า ๆ

**ฟอร์มสองช่องก็นับ** — ชื่อ + แม่ (สายพันธุ์·ชนิดสัตว์ / ตำแหน่ง·แผนก) อยู่แถวเดียว
ไม่ใช่สองบรรทัด · และกล่องต้องกว้างตาม: สองคอลัมน์ `sm:max-w-xl` · สามสี่ `sm:max-w-2xl`

**ช่องกรอกไม่มี `placeholder`** — ป้ายบอกอยู่แล้วว่าช่องนั้นคืออะไร และข้อความจาง ๆ
ในช่องอ่านเหมือนมีค่ากรอกไว้แล้ว · ยกเว้นข้อความในช่อง combobox ตอนยังไม่ได้เลือก
กับช่องค้นหาที่ไม่มีป้าย — สองอย่างนั้นเป็นสถานะ ไม่ใช่คำอธิบาย

**ช่องที่เลือกจากทะเบียนอื่นเป็น combobox ไม่ใช่ `<select>`** — พิมพ์ค้นได้ ·
มีปุ่มล้างค่าเมื่อไม่บังคับ · ทะเบียนที่วันนี้สิบแถว ปีหน้าสองร้อย

**ตัวเลือกของ combobox มาจาก `GET /api/<ทะเบียน>/lookup`** ไม่ใช่ลิสต์เต็ม —
`/lookup` ขอแค่ล็อกอิน ไม่ขอสิทธิ์ของเมนูตั้งค่า · เรียกลิสต์เต็มแทนแปลว่าคนที่ต้อง
เลือกสาขาต้องได้สิทธิ์เข้าหน้าจัดการสาขาไปด้วย · แยก hook และแยก query key
จากลิสต์เต็มเสมอ

**ตัวเลือกเดียวเลือกให้เลย มากกว่านั้นให้คนเลือกเอง** — ทำไว้แล้วที่
`components/common/combobox-field.tsx` ไม่ต้องทำซ้ำในแต่ละหน้า

รายละเอียดทั้งสามข้ออยู่ที่ `docs/standards/web-conventions.md`

**ไม่ต้องมี `<h1>` ชื่อหน้า ถ้า sider บอกอยู่แล้ว** — หัวข้อที่ซ้ำกับเมนู
กินความสูงเปล่าเพื่อบอกสิ่งที่บอกไปแล้ว

**ผลลัพธ์ของ query มีสี่หน้าตา ต้องวางครบ** — กำลังโหลด · ต่อไม่ติด · ว่างเปล่า · มีข้อมูล
และ "ว่างเปล่า" มีสองแบบ: ยังไม่มีข้อมูลเลย กับ ค้นแล้วไม่พบ — คนละประโยค
หน้าที่วางแต่กรณีมีข้อมูล คือหน้าที่ผู้ใช้เปิดครั้งแรกแล้วเห็นจอเปล่าโดยไม่รู้ว่าเกิดอะไรขึ้น

**อะไรที่อ่าน URL ต้องอยู่ใน `Suspense`** — `useSearchParams` และทุกอย่างที่เรียกมัน
ข้างใน (`useQueryState` ของ nuqs ด้วย) · ไม่ห่อแล้ว `next build` ตกทั้งหน้า
ทั้งที่ `dev` กับ `typecheck` เขียวสนิท · แยกเนื้อในออกเป็นคอมโพเนนต์แล้วห่อที่ตัว `page`

**ปุ่มที่ยิง API ต้อง `loading` ตอนกำลังส่ง** และช่องกรอกต้อง `disabled` —
กดสองครั้งเพราะไม่มีอะไรตอบสนอง คือสองแถวในฐาน

## ด่าน 3 · เทส

ไฟล์อยู่ข้างหน้าที่มันเทส — `app/(main)/<หน้า>/page.test.tsx`

**ยิงผ่านสิ่งที่ผู้ใช้เห็น** `getByLabelText('ชื่อผู้ใช้')` · `getByRole('button', { name: 'บันทึก' })`
ไม่ใช่ `querySelector('.btn-save')` — เทสที่ผูกกับ class คือเทสที่แดงตอนเปลี่ยนดีไซน์
ทั้งที่ไม่มีอะไรพัง

### เทสหนึ่งหน้าต้องมีอะไร

```
เห็นอะไร        โหลดเสร็จแล้วข้อมูลขึ้นครบ
กรอกผิด         ไม่ยิง API · ขึ้นกรอบแดง
กรอกถูก         ยิงด้วยค่าที่กรอก · ไปต่อถูกที่
API ปฏิเสธ      ขึ้น toast ด้วยข้อความจาก BE · ไม่ค้างที่ปุ่ม loading
```

**mock ที่ชั้น `features/<โดเมน>/api.ts`** ไม่ mock `fetch` —
mock `fetch` แปลว่าเทสของหน้าจอรู้จักรูปของ envelope ซึ่งเป็นเรื่องของ `api-client.ts`

**ชื่อเทสเป็นไทย** อ่านรวมกันเป็นประโยค:
`หน้าเข้าสู่ระบบ › กรอกไม่ครบแล้วกดส่ง ไม่ยิง API`

**ดูภาพหน้าจอด้วย ไม่ใช่แค่ดูว่าเทสเขียว** — `bun run e2e:shot` ถ่ายทุกหน้า
ทุกระดับสิทธิ์ · เทสที่เขียวหมดยังปล่อยให้บัญชีอ่านอย่างเดียวเห็นปุ่มครบได้
(เกิดจริง 2026-08-26) · ภาพเดียวจับได้ทันที

**ไฟล์เกินเจ็ดในโฟลเดอร์เดียว ให้แยกกลุ่มตามเรื่อง** — `e2e/support/` ·
`e2e/catalogue/` · `e2e/screens/` ไม่ใช่กองรวมกันหมด

**spec เขียนเต็มทุกไฟล์ ห้ามมี suite ที่รับ config แล้วปล่อยเทสทั้งชุด** —
เหตุผลเดียวกับที่เลิกใช้ kit ที่คืนทั้งหน้า · ลอกไฟล์ข้าง ๆ มาแก้ชื่อคือวิธีที่ตั้งใจ
ที่ใช้ร่วมกันได้คือชิ้นที่ไม่รู้ว่ามีทะเบียนอยู่ — `scope` · `auth` · `shot`

**e2e ใช้ฐาน `pawsoft_e2e` ของตัวเอง** ไม่ใช่ `pawsoft_test` ของ `bun test` ·
`bun run e2e:prep` เตรียมให้ครั้งแรก · ใช้ร่วมกันเมื่อไหร่ ชุดที่รันทีหลังลบบัญชี
ที่อีกชุดล็อกอินค้างอยู่ แล้ว e2e แดงยกชุดด้วย 401 ที่ไม่เกี่ยวกับโค้ดเลย

**ชื่อที่เทสพิมพ์ลงหน้าจอต้องไม่ซ้ำข้ามรอบ** — ใช้ `s.unique()` ไม่ใช่ `s.name()` ·
แถวที่เกิดจากหน้าจอไม่มีใครจำ `id` ไว้ลบ และไฟล์ที่ตายกลางทางไม่ได้ `cleanup`

## ด่าน 4 · ตรวจว่าครบ

```bash
bun run typecheck:web
bun --filter @pawsoft/web build
```

**`build` ไม่ใช่ของเกิน** — `next build` จับของที่ `typecheck` ไม่เห็น:
`useSearchParams` ที่ไม่ได้อยู่ใน `Suspense` · client component ที่ import ของฝั่ง server
พวกนี้พังตอน build production ทั้งที่ dev เขียวสนิท

**แล้วเปิดดูด้วยตา** — `bun run dev:web` แล้วเดินให้ครบทุกปุ่มที่เพิ่งทำ
หน้าจอเป็นชั้นเดียวที่ "เทสเขียว" ไม่ได้แปลว่าใช้ได้

## เสร็จเมื่อ

- [ ] ผู้ใช้ระบุแล้วว่าหน้าไหน และหน้านั้นทำอะไรได้บ้าง
- [ ] route ที่หน้านี้เรียก มีอยู่จริงครบ (หรือผู้ใช้สั่งให้ทำล่วงหน้า และเขียนกำกับไว้แล้ว)
- [ ] หน้าจอเรียกผ่าน hook ไม่มี `fetch` และไม่มี `api.*` ในไฟล์หน้าจอ
- [ ] mutation ทุกตัว invalidate query ที่เกี่ยว
- [ ] วางครบสามหน้าตา: กำลังโหลด · ว่างเปล่า · มีข้อมูล
- [ ] ไม่มีสีที่พิมพ์เอง ไม่มี path ที่พิมพ์เอง ไม่มีข้อความปฏิเสธที่ FE เขียนเอง
- [ ] เทสยิงผ่านสิ่งที่ผู้ใช้เห็น และเป็นชื่อไทย
- [ ] `typecheck:web` และ `build` ผ่าน
- [ ] เปิดดูด้วยตาแล้ว

## ห้าม

- **ยิง API ตรงจากหน้าจอ** — cache ไม่รู้เรื่องด้วย แล้วหน้าอื่นโชว์ของเก่า
- **`useState` เก็บข้อมูลที่มาจาก API** — ของชิ้นเดียวสองสำเนาที่ไม่ตรงกัน
- **แปลงเงินเป็น number**
- **พิมพ์สีหรือ path ตรง ๆ**
- ติด `'use client'` ที่ layout
- ทำหลายหน้าในใบเดียว
- แตะ route หรือ service — คนละขั้น ผิดกฎแล้วให้กลับไปเป็นใบใหม่
- เพิ่มปุ่มหรือความสามารถที่ไม่มีใครสั่ง
