ภาพรวมระบบ Paw Soft

ระบบจัดการโรงพยาบาลสัตว์ ตั้งแต่รับข้อมูลลูกค้า จองคิว ตรวจรักษา จนถึงรับเงินและตรวจสอบยอด

1

ผู้ใช้งาน

พนักงานคลินิกและเจ้าของสัตว์เริ่มต้นใช้งานคนละช่องทาง

พนักงาน: username/password · ลูกค้า: Google
2

ทะเบียน

เก็บข้อมูลเจ้าของ สัตว์ ชนิด และสายพันธุ์

Owner → Pet
3

นัดหมายและคิว

คำขอจองเปลี่ยนเป็นคิวเมื่อพนักงานยืนยันและลูกค้ามาถึง

Appointment → Visit
4

ตรวจรักษา

สัตวแพทย์บันทึกอาการ ผลวินิจฉัย ยา และรายการรักษา

Visit + Service + Drug
5

การเงิน

เคาน์เตอร์ออกใบเสร็จ รับเงิน และแนบหลักฐาน

Visit → Invoice → Payment
6

ตรวจสอบยอด

บัญชีตรวจสอบและยืนยันยอดโดยต้องเป็นคนละคนกับผู้ส่งยอด

Maker-checker

Data Flow: เส้นทางข้อมูลปกติ

อ่านจากซ้ายไปขวา ข้อมูลหนึ่งเคสจะเดินผ่าน 6 ขั้นตอนนี้

1
รับข้อมูลลูกค้าจองผ่านเว็บ หรือพนักงานรับจองทางโทรศัพท์ / ลงทะเบียน walk-in
2
ยืนยันและ Check-inพนักงานตรวจข้อมูล กดยืนยันนัด และกด “มาถึงแล้ว” เพื่อสร้างเลขคิว
3
เข้าคิวตรวจระบบจัดลำดับตามความเร่งด่วนและเวลามาถึง พนักงานเรียกคิวเข้าตรวจ
4
บันทึกการรักษาสัตวแพทย์บันทึกน้ำหนัก ผลวินิจฉัย หมายเหตุ ยา และรายการรักษา
5
ออกใบเสร็จเคาน์เตอร์คำนวณส่วนลด ออก invoice และบันทึกเงินสด โอน PromptPay หรือบัตร
6
ยืนยันยอดบัญชีตรวจยอดและสลิป ถ้าถูกต้องจึงยืนยันใบเสร็จและปิดคิวเป็น DONE

Workflow: ผู้รับผิดชอบแต่ละขั้น

ระบบแบ่งหน้าที่ชัดเจน เพื่อให้ข้อมูลเดินต่อได้โดยไม่ข้ามขั้นตอนสำคัญ

A
เคาน์เตอร์รับนัด ลงทะเบียน Check-in เรียกคิว ออกบิล และรับเงิน
B
สัตวแพทย์ตรวจสัตว์ บันทึกผลวินิจฉัย ยา รายการรักษา และกดตรวจเสร็จ
C
บัญชีตรวจยอดที่เคาน์เตอร์ส่งมา ตรวจสลิป และยืนยันหรือตีกลับ
D
เจ้าของสัตว์จองนัด ดูประวัติ ดูใบเสร็จ สแกน QR และส่งสลิปของตนเอง

กฎสำคัญของระบบ

กฎเหล่านี้ช่วยป้องกันข้อมูลผิดคน ผิดยอด และการเข้าถึงเกินสิทธิ์

แยกบัญชี

พนักงานใช้ session หนึ่ง ส่วนเจ้าของสัตว์ใช้ Google session อีกชุด ข้อมูลจึงไม่ปะปนกัน

จำกัดข้อมูลเจ้าของ

เจ้าของสัตว์เห็นเฉพาะข้อมูลของตัวเอง โดย service กรองด้วย account id ทุกครั้ง

Maker-checker

ผู้ส่งยอดกับผู้ยืนยันยอดต้องเป็นคนละบัญชี ลดความเสี่ยงจากการยืนยันยอดตัวเอง

ตรวจสิทธิ์สองชั้น

Web ซ่อนเมนูและปุ่มที่ไม่มีสิทธิ์ และ API ตรวจ permission ซ้ำก่อนทำงาน

เงินเป็นข้อความ

ยอดเงินใช้ string เพื่อไม่ให้ทศนิยมคลาดเคลื่อนระหว่าง Web, API และฐานข้อมูล

เก็บประวัติ

การเปลี่ยนแปลงสำคัญมี audit และข้อมูลที่มีประวัติอ้างอิงจะไม่ถูกลบแบบทำลายทิ้ง
